# Settings extension

Model settings use a dedicated tab within the same inspector. Select the target computer, connection (ChatGPT account, OpenAI API, or Claude), model and supported reasoning setting. The current saved choice applies to newly started tasks; an existing task retains its immutable model configuration through continuation and restart. Memory extraction uses its source task's model; new responsibility evaluations use the selected model. Display the daemon's reported connection availability separately from a saved configuration. Saving is not a successful inference or credential-validation claim.

API keys are write-only password fields kept only in mounted component state and cleared after save or provider change. Omission retains that provider's saved key; the client never receives a saved key or ciphertext. Use the server revision for optimistic updates and discard responses for a previously selected computer. No automatic switch from ChatGPT to paid API and no Ultrafast option. An omitted reasoning effort means provider default; do not label it Light without verified provider semantics.

Extends the existing DESIGN.md system; no new visual theme or dashboard. One settings entry opens the existing inspector. Three compact tabs separate workspace instructions, skills and MCP. VM-scoped tabs display the real target computer. Rows show saved configuration and independently observed runtime revision/state, with a last-observed time rather than invented live indicators.

Use existing surface, ink, muted, line, accent and status tokens. Settings rows use 16px corners, 16px padding and 12px gaps. Edit sheets are native modal dialogs, width640px maximum, with fixed header/footer and a scrollable form. On mobile they fit the viewport with safe-area spacing. Native focus containment/Escape plus explicit cancel are retained; close restores the invoking focus. Enter submits only normal single-line fields, not Markdown textareas. Existing panel motion stays unchanged; sheet entry is a short opacity/8px movement and reduced motion removes translation.

Instructions and Markdown are text, never executable HTML. Skill imports preserve the raw document and require editable descriptive fields. MCP exposes only supported stdio/http fields; arguments are a JSON string array. Existing secret keys can be shown, values cannot. Keep/replace-all/clear-all semantics are explicit; replacement values use password inputs and live only in the mounted editor. Saving never implies the VM has connected. Ready/connected/disabled states require matching observed revision; stale VM or failed polling is shown honestly.

Read current modern-web-guidance dialog/HTML guides. Native showModal provides focus and Escape; mobile platform dismissal is progressive enhancement, not assumed Safari support. Use labelled native form controls, no positive tabindex, no new dependencies. Validate actual CRUD/import/secret omission/error/retry against the real API, at375/768/1280, with keyboard and reduced-motion evidence.
